# HTTP request timeouts and TLS transport cleanup

Baseline 4c2eca7 passed Codemagic. Real Java URLConnection timeout setters/getters, negative validation and doOutput fix. HTTP connect wraps the existing GCF handler in a bounded per-OS-thread request scope. TCP connect inherits the requested timeout; existing socket read loop uses current request read timeout (including reused connections). TLS BIO reads use poll timeout. On transport timeout, shut down only the registered owner fd, latch the timeout, stop retry admission, discard partial data and throw SocketTimeoutException at the Java HTTP boundary. Legacy GCF bulk read cannot safely consume -2; it sees EOF only during a latched failed HTTP request. No fake server response. No global timeout or Java object in the scope. DNS remains synchronous; connect timeout is TCP deadline after DNS, TLS handshake has per-read wait limit not one whole-handshake deadline, writes have no deadline. Non-POSIX rejects nonzero timeout scopes. Full HTTP semantics (redirects, status/error stream, cache headers, HTTP methods) not claimed complete.

Cache key retains query; no cache on POST/custom headers; fix setRequestProperty, doOutput and empty POST, close input/output stream, do not cache a timed-out body. TLS complete write loop, EOF instead of synthetic NUL, initialized/connected guards and idempotent sequential close, cleanup on failed init/connection. Concurrent use/close still needs review, certificate verification policy unchanged (legacy optional verification is a separate security gap). No shared images in this change. Real bundled boot ABI is checked in CI; current environment cannot inspect binary boot JAR or run iOS. Existing regression tests extended for native scope and preserved GCF behavior.

Regression fixtures now cover Java timeout cleanup while scope is still active, cache query identity, headers and empty POST; native timeout stops only its own descriptor and leaves other sessions active; TLS partial-write/EOF/close helper execution uses scripted library results. These are host fixtures, not a real iOS HTTPS integration test.
