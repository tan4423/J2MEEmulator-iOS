# Shared prepared method code templates

Baseline 297c9d6. This is a partial shared parsed-metadata implementation, not shared linked classes. The byte-order conversion in _changeBytesOrder is determined by the original byte stream; the branch label table at that point contains integer offsets and -1 sentinels only. Cache exact original method bytes, converted bytes, and these integer offsets. On a hit copy into independent mutable interpreter and JIT-source buffers; rebuild a private label table. Keep per-method getter/setter checks, locks and JIT initialization. No JClass, FieldInfo, MethodInfo, classloader, constant-pool resolution or Java heap pointer is shared.

Only methods of 128..16384 bytes, maximum 2048 branch offsets per template, 2048 entries and 4 MiB process-wide dynamic budget. Tiny methods retain original path; sampled hash selects candidates only, full byte comparison decides identity. Unknown opcodes or failed label insertion cannot publish. Lock contention, allocation failure or full budget fall back to ordinary conversion. No persistent cache; memory pressure trim uses existing bridge callback and epoch prevents a pre-trim miss from publishing stale entries. Caller buffers never depend on cache lifetime. First startup may cost extra copying; expected advantage is reduced repeated conversion/branch insertion for longer methods, not proven CPU or RAM savings. No network, UI, scheduler, JAR or mutable-state changes.

Host cache fixture compiled with ASan/UBSan before integration using stub VM structs/Pairlist; exact header code. Does not exercise the full class conversion, native iOS build or game rendering. CI and clone-start timings required. Keep complex linked metadata and executable opcode state private unless measurements justify further architectural changes.
