# Performance stage 2: native metadata string hot paths

Optimize existing Utf8String functions, not Java String semantics: bulk append with one reserve/copy, self-alias preservation and hash invalidation, single-byte normalization without allocation, length/identity rejection before hash and libc memcmp. Checked signed capacity growth and failed allocation preserves the old string. Keep generic replace path, class initialization and dispatch semantics; fix null superclass check for interface method lookup. No JIT, game JAR change, new shared Java state or third-party emulator source. Existing mutable metadata/hash synchronization and general allocation callers are not comprehensively audited by this change. No iOS speedup claimed before matched measurement. Host regression includes actual source with allocator injection; CI/device pending.
