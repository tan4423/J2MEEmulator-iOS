# Native String.charAt0 leaf candidate

Measured E1 hotspot String.charAt / String.charAt0. Source audit: jni_std.c maps bootstrap java/lang/String.charAt0(I)C to java_lang_String_charAt0, which obtains the receiver/index from the native frame, calls jstring_char_at, pushes an unsigned UTF-16 code unit, and returns normal. Normal interpreter allocates/initializes a Runtime/local variable frame and disposes it on return. Candidate avoids only that native frame for a valid read. Java String.charAt wrapper is unchanged (including exceptions); no change to String representation, JAR, GC, render, gameplay, or JIT.

Independent JARBOX_VM_CHAR_LEAF_EXPERIMENT=0 by default. Mode 1 only, non-debug/non-JIT, no stop/suspend/JDWP/breakpoint, exact already resolved native function pointer, nonstatic nonsynchronized native, correct slots, initialized bootstrap declaring class. No lookup or native binding on candidate path; unresolved calls run ordinary interpreter. Current JVM's String shortcut fields must belong to the exact declaring class, fit its layout, have expected size/reference shape and be nonstatic/nonvolatile. Require exact receiver class, actual char[] storage and valid count/offset/index. Read current fields each invocation using memcpy (including potentially unaligned fields); no references or values cached, no allocation or Java call. Invalid slice, negative/out-of-range index, null, foreign class or insufficient stack returns to original native path without modifying stack. Does not attempt to fix malformed-input behavior of the old native implementation. No synthetic exception or sentinel introduced. Candidate is deliberately conservative and may be slower due to guards. No correctness claim for full VM/concurrent GC until integrated differential.

Per-owner char_leaf_calls batched 64 on owning Java thread. E1 checkpoints still run; successful leaf bypasses existing native E2 timing because native call no longer happens, so do not interpret lower native share as CPU savings; total CPU and matched frame cost required. Full raster and scoped Core off retained. Other experiments unchanged.

Local exact helper + C layout doubles compiled and ran GCC and Clang ASan+UBSan: all 65,536 UTF-16 units (including isolated surrogate, NUL and 0xffff), 100,000 deterministic nonzero/zero-offset slice accesses, 30 rejection cases including foreign shortcut/receiver, malformed slices and unchanged stack on fallback. This is a host fixture, not Java or MiniJVM differential, not an iOS build or performance benchmark. Source wiring test added; integrated VM validation and iOS CI pending. No device install requested.
