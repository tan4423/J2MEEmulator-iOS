# Block IR dispatch lookup refinement
The live IR sample #1038 executed 457,066 spans and 2,375,327 tape operations in about 10 seconds. This is evidence of a hot path, not a lookup-time profile. Replace the old 64-bit low-PC filter + binary search on every positive with a 64-byte immutable bucket table: empty misses return immediately, unique buckets compare one exact PC, collisions retain binary search. Same spans, effects, stack writes, safepoints and fallback. Each plan adds 56 bytes counted in its existing owner/shared publication budget. The tighter memory budget can reduce plan admission; measure it rather than asserting a win. No JIT, JAR edit, timing or gameplay change. Existing differential fixture plus exhaustive collision/unique/invalid-PC check. CPU benefit unmeasured; do not promote solely on admission count.
