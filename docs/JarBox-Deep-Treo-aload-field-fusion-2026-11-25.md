# Deep Treo: bounded aload/getfield dispatch fusion

Baseline 6172b1d. Static instruction-boundary scan of the six game JARs found short aload_0..3 immediately followed by getfield: original NSO 9,895, Nick 13,977, TrungDucTV 10,620, NST X1 10,315, V9 NOKEY 11,527, V9 NSOTIEN 11,538. These are code sites, not dynamic frequency. Prior fast path counters do not establish CPU savings. The interpreter already uses signed-in-app computed-goto dispatch and quickens field reads. This patch chains the existing short aload handler directly into one of six already-quickened getfield handlers. It eliminates one return to the dispatch loop for eligible pairs; no field or object caching, no new bytecode or code rewriting, no JIT. Keeps original stack operations, PC at field for null exception, width and resolution logic. Cold getfield, other next opcodes, truncated operands, debug/profiling and switch paths stay unchanged. No safepoint exists between these forward opcodes in the ordinary non-JDWP loop. No new quickening publication mechanism; uses same existing resolved opcode and handler. Can disable at build time with TREO_VM_ALOAD_FIELD_FUSION_DISABLED. Approximate per-session count batched 256, undercounts partial batches. Additional check on short aload may offset gains; use matched benchmark before broadening. Host fixture extracts actual macro and tests route and stack/PC model, not full interpreter or device performance. No game changes or new timer.
