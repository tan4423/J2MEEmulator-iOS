# Deep Memory: collector-local deferred callback index

The focused device run at 5e8bc1d recorded about 77–80k scanned objects per collection, with deferred processing consuming 1.39/4.64/1.42 ms worker CPU per A1/B/A2 cycle. This phase previously walked every heap node again after mark, although only instances with finalization or weak-reference effects can participate. Those are inclusive measured phase costs of the old build, not a forecast for this candidate.

This independent compile-time experiment (JARBOX_GC_DEFERRED_INDEX_EXPERIMENT=1, default off) maintains a non-owning vector in reverse heap-list order per collector. New objects are classified once at the existing stopped-world batch merge; arrays/classes are not callback candidates. An instance is excluded only if it is not weak and its class is already CLINITED with no finalizeMethod. class.c resolves finalizeMethod during class_clinit before publishing CLINITED; jvm_util.c instance_create sets the weak flag before gc_obj_reg and instance_copy preserves it. Noninitialized classes stay in the index, including ones that acquire a finalizer later. Do not assume a class with a finalized instance is free of weak-reference effects. JDWP and terminal cleanup disable the index.

Backward iteration retains original callback order, including interleaved finalizer and weak enqueue and the original reverse remark list; it neither skips required callbacks nor changes mark, GC cadence, or sweep. Update happens before any root-copy failure can return; compact after deferred remark and before destruction using the same mark test as sweep. No shared pointers across VMs, no extra root, no per-object metadata growth. Cap 16384 pointers (128 KiB on arm64), sticky whole-list fallback on cap/OOM, free after worker join. The extra classification occurs during STW; measure pause and total CPU before promoting. No assertion about actual candidate cardinality or win on iPhone.

Local extraction model: actual callback-loop body with synthetic independent heaps and callback/mark stubs; 11818 exact callback/sweep model cycles, allocation/cap failures, late class initialization, STOP, paused entry and merged-root abort. Clang ASan/UBSan passed. CI additionally builds the actual MiniJVM with the candidate, compares independent owners with index on/off using the existing allocation-heavy IntrinsicMain (both prior intrinsics off), and requires actual indexed passes and worker cycles. That workload is not a full real weak/finalizer oracle or game. New CI result pending at commit; no iOS integration or device claim. Keep the runtime default and existing residual configuration unchanged until the new gate is green and a dedicated callback/benchmark gate is justified.

## Callback and coverage gate

The initial actual MiniJVM host A/B allocation fixture gate passed at b3b9bba (run 45956627974, job 140364495735); full workflow was still running when checked. The new host-only fixture keeps 16,000 ordinary instances alive per owner, releases three rounds of 64 inherited-finalizer instances and weak referents, checks exactly-once finalization, weak clearing, strong-root retention and owner-specific field values. Two OpenJDK -Xint processes produced the same expected digest PASS 192 383976000 locally. It does not require callback order to be identical across asynchronous GC schedules. Instead the test-only stopped-world shadow independently checks that the actual index is an ordered subsequence of the actual heap with every potentially effectful instance included. Host counters require actual finalizer and weak enqueue calls, indexed passes, at least one snapshot with 10,000+ excluded nodes and no candidate admission in the control. The shadow deliberately adds a full heap walk; visit/omission counts describe coverage and are not CPU measurements. New real MiniJVM callback fixture awaits CI, including boot-jar API compatibility. Runtime default, production index and iOS flags unchanged.
