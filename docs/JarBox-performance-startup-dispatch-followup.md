# Startup and dispatch follow-up

Production changes: (1) immutable PIC slots now answer duplicate publication and full-cache rejection without taking the writer lock; acquire loads retain the prior release-publication contract and empty slots retry under the existing lock. (2) Loose classpath files read into an unpublished ByteBuf tail; the previous readable prefix and cursors survive OOM or short reads. Capacity may grow before a short read. (3) A classpath lookup reuses one private ByteBuf across unsuccessful probes, clearing both cursors before each read, preserving first-success order and session-specific ZIP counters. If the initial buffer cannot be allocated, stop the lookup. No shared mutable VM data, JAR edits, game timing changes, or JIT activation. This is not an implementation of compact stack or decoded interpreter.

Local extracted-source tests: GCC and Clang strict C11 and Clang ASan/UBSan, both dispatch modes (2,000 batches per mode), 400,000 concurrent fixed-result iterations, and 1,000 classpath/file fault-injection batches per compiler configuration. The file test uses actual loose files and production ByteBuf functions; ZIP routing, UTF-8 strings and VM layouts are modeled. Three ZIP probes use two VM allocations instead of six in the model. Not a measured game startup speedup. Full existing suite, Xcode integration and game execution remain unverified.

One device candidate: JARBOX_VM_PERF_CANDIDATE=1 opts in to the two previous constant fusion experiments in the same build. Default remains 0. Separate switches remain available. Packaged Info.plist and every Flight Recorder line include JarBoxPerfProfile (const-arith-N_const-branch-N, or unknown for older builds). CI verifies the packaged value. Commit and profile identify a tested build; preserve matching dSYM. Do not request an IPA test while CI is queued or failing. Use original Ninja School, then representative mods, warm starts and multiple tabs in one installed build. One combined test can establish compatibility and aggregate behavior, not isolate speedup of each optimization.
