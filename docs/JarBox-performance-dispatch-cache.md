# Performance stage 3: bounded virtual dispatch cache

Independent implementation of standard polymorphic inline caching. Ordinary iOS interpreter: two immutable receiver-ID/MethodInfo slots per constant method reference replace eager Pairlists. Acquire/release publication with existing loader lock for writers; no map allocation or lock on hits, no cross-VM state. VM-local monotonic IDs saturate rather than wrap; an old class address cannot match a new class. Cache only ordinary instance receivers with exact class, bootstrap or same-loader method owner (GC retains their class/loader and defined classes). Arrays, unrelated loaders and full caches resolve normally and execute directly if not retained, preserving getter/setter and virtual/interface PC width. No negative caching. Compile-time baseline JARBOX_VM_INLINE_DISPATCH_DISABLED; optional JIT helper lazily allocates legacy Pairlist, not enabled. Correct legacy interface pool selection and interface list destruction. Existing legacy unload/lookup semantics outside new cache not comprehensively certified. 32 extra bytes per reference on 64-bit replace two eager allocations (Pairlist and four Pairs) on ordinary iOS path; actual savings depend on workload. Highly polymorphic calls can lose cache coverage, measure before expansion. Host regression exercises publication, exhaustion, unique IDs and two pools; interpreter integration, custom classloaders and iOS benchmark pending. No game JAR, tick, network, RMS or third-party implementation changes.

Fast opcode misses resolve and execute directly on the new path, avoiding shared opcode rewrites for polymorphic/full sites. Slow first-use getter/setter path remains; fast misses call the actual method rather than getter/setter shortcut. Missing method still throws (the game-specific verbose slow-path probe is not emitted on this new fast-miss path). Linux host: exact production header blob 9f29a0d08bd327aaa92ca905bc6a1464a5462e90 compiled with GCC and Clang strict C11 and Clang ASan/UBSan; all three passed 400,000 concurrent read iterations and 10,000 identity/cache cycles. This checks the primitive cache only, not Java method resolution/GC lifetime or end-to-end performance.

Host handler coverage: `test_dispatch_handlers.py` compiles the actual two fast opcode bodies and lookup/publication helpers with modeled VM structures and the production cache header in both inline and Pairlist configurations. Covers full cache, repeated miss, null receiver, resolver failure, exception PC/stack, array and foreign-loader rejection, exhausted identity and independent VM references. Local GCC/Clang strict C11 and Clang ASan/UBSan passed 2,000 batches per configuration using extracted bodies; full interpreter, GC lifetime and iOS validation remain pending. No runtime source changes in this test checkpoint.
