# Performance stage 1: exact archive name index

Independent implementation on JarBox source, based on standard hash indexing and binary search, not on third-party emulator implementation. miniz's case-sensitive lookup scans the entire central directory; its built-in sorted lookup is case-insensitive and cannot replace it. Build optional immutable names/ordinal index when a read-only cached archive with >=32 entries is admitted. Full byte comparison, first matching original ordinal, exact case, existing before/after file identity checks; allocation/unsupported names/size fallback to original miniz. Additional bounded 512 KiB per archive, four readers maximum, released on trim/eviction. No Java objects, game state or bytecode shared. No changes to ZIP writer, ordinary ZIP APIs, game timing or JIT. Cold index construction may cost more for infrequently accessed archives; no device startup or CPU improvement claimed. Regression compares indexed lookup against miniz for every name, duplicate, long name, case, miss, trim and replacement. Full CI/device baseline pending.
