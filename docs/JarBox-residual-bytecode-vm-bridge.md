# Whole-loop residual: executable bytecode bridge to real VM oracle

Nicknsonet is the primary optimization target; TrungDucTV and V9 follow, original Ninja is the compatibility reference. Previous effect-preserving CFG work stays intact. This is a test-only backend, not a release optimization or a game JAR rewrite.

- tools/ninja_residual_bytecode.py lowers retained typed stack-slot operations to ordinary JVM instructions. Existing constant-pool indexes are reused for field reads/writes and q3/m3 calls; branches are relocated and effect instruction PCs recorded. Primitive and reference local slots are separate. All 101 k1 static read sites and four write sites remain roots.
- tools/ninja_residual_fixture.py generates two isolated test classpaths. Synthetic corpus-free fixture is used in CI; optional --archive takes the exact previously admitted Nick SHA. Only a temporary class fixture is replaced, preserving the CP and other selected methods. No original archive bytes are changed or committed.
- Host MiniJVM smoke residual_diff starts two independent JVMs concurrently, original and residual classpath respectively, compares 2000 indexed final-state/exception records exactly and requires a nonvacuous PASS footer. Both workloads request GC periodically. No production activation; no iOS changes. Synthetic CI fixture is not real game gameplay.
- Local OpenJDK 21 -Xint -Xverify:all with local reproduction of the HEAD IR functions: synthetic 85 -> 49 retained IR operations, 246 faults, 1930 changed-state cases; exact Nick k1 751 -> 412, 305 faults, 1538 changed-state cases. 2000 records plus footer matched byte-for-byte for each fixture pair. The backend/fixture files were tested locally; upstream IR was read through connector and reproduced locally because Git clone DNS failed. CI is the authority for exact checkout integration. The generated Nick fixture bytecode is 2237 bytes, not optimized dispatch: loads/stores used to make slot IR executable may increase interpreter work. These counts and tests are not CPU savings, ordered effect trace proof, original exception-PC equivalence, actual game execution, or actual MiniJVM result yet.
- The no-op receiver double deliberately omits the real wrapper's field reads/null/linkage and graphics side effects, and the reference locals may extend lifetime. No runtime admission is authorized. This backend provides the next real-VM verification boundary, not a method to ship modified class files. Actual effect handlers, original PC mapping, GC roots/safepoints, per-owner Canvas admission, wake/STOP, real wrapper effects and larger elimination remain required for an immutable native micro-op plan.

Local reproduction commands (fresh directory): python3 tools/ninja_residual_fixture.py /tmp/jb-fixture --archive PATH_TO_EXACT_NICK.jar; java -Xint -Xverify:all -cp /tmp/jb-fixture/original ResidualMain X SAVE_A and corresponding residual classpath SAVE_B (create save directories first); cmp SAVE_A/residual.txt SAVE_B/residual.txt. Actual host suite: bash tools/host_multivm_smoke/run.sh asan 1 residual. No device build required for this stage.
