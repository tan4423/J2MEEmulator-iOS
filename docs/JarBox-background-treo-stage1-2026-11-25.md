# Background Treo stage 1

Baseline a061063, Codemagic SUCCESS. Scope: 2D lifecycle preparation, not a guarantee of continued iOS execution. No background entitlement, audio keepalive, location, JAR changes or JIT. Default closed scene gate; main scene active opens it, inactive/background/disconnect closes it. The live 2D renderer and diagnostic Metal replay acquire the same gate before committing and release after completion. Close first rejects new submissions, then drains a previously accepted command. CPU CoreGraphics fallback preserves the original ordered drawing; queued UIKit frames lose publication authorization while inactive. The existing visible generation is retained. The gate does not cover OpenGL/3D, and the main-thread drain latency still needs device validation.

Actual background entry (not Control Center alone) enters existing owner-scoped Treo for an already running, conservatively classified 2D visible session with no pre-existing Treo mode or startup watchdog. No implicit focus change, UI dismissal or JVM restart. Resume clears only the token whose scene Treo was acquired, if it remains visible and not independently parked. Unknown/exclusive 3D and startup are not opted into this transition. The existing Treo proof/fallback and GC pressure rules remain.

Host C gate: Clang/GCC strict C11 and Clang ASan/UBSan, 10000 open/close transitions and 100 drain races passed. These test pthread/atomic gate semantics, not Apple Metal, Swift lifecycle or actual background progress. CI and device validation pending. Next: audit separate 3D GL paths, process-wide audio session ownership/interruption and explicit background playback, plus real per-session progress diagnostics. iOS may suspend or terminate the app; do not claim background uptime from this change.
