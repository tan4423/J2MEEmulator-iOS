# Persistent flight recorder v1

Use Thư viện → JarBox menu → Xuất nhật ký sự cố (also game Debug menu). Share or copy text including the latest background report. After an OS kill reopen JarBox and export before extended additional play. No automatic upload. Two rolling 512 KiB files in Application Support, excluded from backup; protection available after first device unlock. Each line carries process run UUID, exact build, sequence and Unix time; boot includes hardware model. No game names, paths, account data, input or network payloads.

Utility-queue timer checks every 5s after a game launch request, stops after three observed empty samples. Persist ordinary snapshots every 60s, phase changes, gaps >15s, pending first frame/cleanup, busy registry or observed process CPU >=60% of one core every 5s. Diagnostic threshold, not Apple's guaranteed budget or automatic stop. Native sampler uses trylocks, phase-only for STARTING/CLEANUP, callback leases for RUNNING, up to 128 Mach thread reads per detailed sample, no heap walk or background assertion. Counters cumulative per token within a run; invalid samples flagged. Process CPU independent of slot availability. App scene transitions, launch request/admission, first surface, startup timeout, stop request, worker return/failure and memory warning recorded. No gameplay/GC/renderer/audio policy changes.

Best effort only; timer cannot run while suspended, a killed process cannot write a final event, OS/device lock and storage errors may lose evidence. Sampling adds some CPU/writes; measure on real hardware. Phase-only before native publication, no native stack capture; use matching dSYM and iOS resource report for precise code attribution. Rotation discards oldest data. Host test extracts journal/policy; native wiring is source assertions, not native stress. CI/device validation required.
