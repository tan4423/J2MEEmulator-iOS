# Flight Recorder scoped export and native paint attribution

Current run is the process UUID, not a game tab or a new export window. Quick TXT export includes only exact run-prefixed rows in the existing two bounded journal files, with explicit scope; prior build and background report excluded. Full export retains up to two 512 KiB journal files plus separate latest background report and incidents, compressed on the existing export queue with miniz raw DEFLATE, gzip header, CRC32 and ISIZE; fall back to lossless text if compression or temporary write fails. Temporary file is removed after sharing, or if presentation is no longer possible. No continuous compression or timer, no change to sample format or historical retention. Clear history explicitly deletes only current.log and previous.log, writes a new marker and sample, retains game data and separate background report. User confirmation required. Previous data may already have rotated out even for current run. Full raw counter schema deliberately retained (including zero fields) so older decoders do not misinterpret missing as zero.

E2/E5 pilot: new default build native-paint-diag-1, ninja-core-0, paint-qos-0 and four interpreter experiments off. Full-raster compatible mode 1 is the measurement control; override JARBOX_NATIVE_PAINT_DIAG=0 for same-source uninstrumented control or JARBOX_NINJA_CORE_EXPERIMENT=1 for separate sink trial. No gameplay, tick, network, RMS, JAR, JIT or mode-8 changes. Existing timer is unchanged. At existing negative-stamp paint begin/end select one of every 32 mode-1 paints per owner, varying position. In selected frames time outermost resolved native method function calls with thread CPU clock, grouped LCDUI NativeBridge draw, other LCDUI, other native. These inclusive native functions contain parameter decoding, bridge/lock/cache/text/pixel work, offscreen draws and possibly nested Java; NOT pure CoreGraphics raster. Unmeasured direct fast paths and clock/dispatch overhead remain in residual. No native-method-pointer retention across callbacks, no Mach suspend, no per-opcode instrumentation. Nested paint, clock errors, mode not 1 at end or inconsistent totals discard whole frame. A transient transition away and back within one paint cannot be ruled out. Pixel counts for outermost sampled drawRGB/getImageRGB are requested sizes, not actual processed pixels, not all calls; do not scale uncritically. No createRGBImage count yet. Publish cumulative per-VM counters on paint end, relaxed atomics, snapshot not a transaction; use long stable intervals, ignore inconsistent deltas. Compare selected_cpu_ns / selected_frames against plain_cpu_ns / plain_frames for observer distortion; ordinary frames still pay selection/TLS checks. Native draw share of selected CPU = draw_ns/selected_cpu_ns; remaining inclusive native groups similarly, residual is not proven Java game logic. Do not multiply by total process CPU unless using matched paint CPU fraction. No time for scope setup/reset/flush outside paint callback, no new main-thread/logic/network counter. E1 asynchronous PC/method sampling not implemented; unsafe suspended-stack pointer inspection is not substituted. E3 same-session A/B/A and E7 logic effect journal remain open. No native library optimization authorized by these measurements.

Local tests: GCC, Clang, Clang ASan/UBSan passed 100,000 selection blocks and 1,000 gzip framing round trips using system zlib (not actual iOS miniz or share sheet). Production helpers and fixture exact hashes checked before publication. Swift store tests and source wiring are wired into CI; device/CI not yet verified. Test one original Ninja or same Nick version, same scene, mode1 for >=180s while app library remains foreground, export quick while still parked. For observer impact compare matched uninstrumented build only if needed. No numerical CPU saving claim.
