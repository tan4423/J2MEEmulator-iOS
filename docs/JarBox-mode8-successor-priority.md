# CPU target: exceed the old Deep Treo, not the current compatible baseline

Historical mode8 user reports about 10–15% single tab; long two-tab log worker CPU 10.8/14.4% per owner, excludes untracked process overhead. Different measurement, scene, thermal and configuration from E3 mode1 42.10–42.53% total process. Mode8 automatic quarantined 7b47987 after stall/multitab/CPU resource incident, cause not proven. Do not reactivate unconditional paint skipping. E3 scoped sink reduced paint CPU but raised process CPU by 2.30 percentage points, so do not promote it. Goal under 10% total single-owner process CPU in matched active gameplay, not just reduced paint or battery estimate; then multitab per-owner worker + total process and actual progression checks. To reach 10% from 42.3% needs about 76% total CPU reduction; keeping outside-paint ~8.4% would require ~95% reduction of paint cost. Small intrinsics alone cannot achieve this.

Priority is effect-preserving elimination of entire provably render-only loops, retaining writes, queries, exceptions, offscreen pixels, synchronization, network, tick and I/O. Existing M0–M2 wrapper plans are not full-loop proofs, no executable overlay yet. Never execute original and sliced paint sequentially on same live mutable state as a correctness oracle. Unknown/fault -> original path. Full redraw on resume. Keep program-slice admission strict, no new whole-paint skip and no JIT/JAR changes. Need prove loop and cross-frame dependencies, then integrated MiniJVM differential with independent state and matched workload. Renderer acceleration is secondary but useful for fallback.

This commit removes 10 indirect JNI localvar getter calls per native drawRegion while preserving the native frame and renderer. Original JNI implementations delegate directly to inline localvar_getLong/getInt. On existing compatible immutable crop path, borrow fullImage from retained RenderImage instead of redundant CGImageRetain/Release. img remains acquired until after crop draw; crop still owned, cache ownership, replay capture, draw order, transforms, graphics state, pixels and all fallback paths unchanged. No new feature switch or timer, no mode8 enable. GCC and Clang ASan/UBSan ran exact slot helper/fixture on 100,000 layouts with signed coordinates and two-slot longs; layout doubles, not full integration or CG pixel test. Source wiring test added. No quantified CPU gain until real matched benchmark. Prior host-intrinsics check for d479346 SUCCESS; its macOS job still queued at this review. No new device test requested. Stop piling on diagnostics as a substitute for reducing measured process CPU.
