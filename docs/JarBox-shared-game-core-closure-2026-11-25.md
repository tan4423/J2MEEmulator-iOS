# Shared Game Core: implementation boundary and validation (2026-11-25)

Baseline 212af09. Freeze the sharing architecture here pending device measurements: shared read-only JAR readers (4 LRU), exact entry bytes (6 MiB), negative lookups (128 KiB), prepared bytecode/branch templates (4 MiB), decoded images (6 MiB nominal). These are cache budgets, not all native memory. Each JVM retains private execution buffers, linked classes, heap, static fields, GC, handles, mutable images, account/RMS and sockets. No raw Java pointers are shared. Do not attempt full linked-metadata or execution-buffer deduplication without measured benefit; CPU is the priority. No scheduler changes in this checkpoint.

Add cumulative startup_shared snapshots at constructor/startApp. ZIP probes count archive attempts, positive hits count successful identity-validated cached copies, negative hits count validated cached absence; hit_bytes are uncompressed bytes reused (not RAM saved). Prepared candidates are eligible methods, hits are successful copies of prepared bytes and branch offsets, and hit_bytes count converted byte length. Hits may include repetition within one VM, not only cross-tab reuse. Per-class local counters are merged into the owning session; TLS scope restored before class registration/linking; no per-method atomic or global counter. ZIP counters are aggregated once per classpath request. Separate cumulative snapshots use relaxed atomics, not a simultaneous transaction across workers. No new worker, timer or lock.

Device acceptance: cold launch, then 2nd and 3rd clone of same JAR, then 5–10 concurrent clones and repeat start/stop. Compare constructor and request_to_surface times, shared counters, image stats, RAM, CPU, and ensure stop/relaunch, RMS/login isolation and image rendering. Repeat with another game; confirm no stale cache after JAR replacement and trim. Record cold overhead and warm improvement before raising budgets. If prepared cache gives no material gain or hurts startup, disable/revert it rather than extending it. CI and device validation pending; freeze scope, not a performance claim.
